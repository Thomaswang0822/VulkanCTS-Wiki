Concrete problem: mirror a 4×8 work tile

Think of one warp-like subgroup with 32 shader invocations. Each invocation owns one matrix slot, initialized to its thread ID. The toy goal is to mirror left and right endpoints.

payload and guard

Payload and guard are separate per-invocation slots. For T1/T6, T1 writes payload[1] = 1, then signals guard[1]; T6 checks that slot after observing guard[1].

Payload bufferpayload[1] = 1
payload[6] = 6
Guard bufferguard[1] = ready
guard[6] = ready

release and acquire

Pick T1 as writer and T6 as reader. No extra swap temporary is required; the connection is made through payload[1] and guard[1].

T1 writer
write payload[1]
release + signal guard[1]
⟶
T6 reader
observe + acquire guard[1]
read payload[1]
from familiar mirror pairing to message-passing vocabulary←/→ · N notes · S presenter · O overview
This slide uses a simplified warp-like 4 by 8 tile as intuition. In Vulkan terminology, the real representative case uses shader invocations in a subgroup; "warp" is only a familiar mental model, not a Vulkan API term. The mirror example makes partner pairing concrete: thread 1 and thread 6 are a left-right pair in the first row. Payload is not a single variable; conceptually it is a per-invocation slot in a payload buffer, so payload[1] stores T1's value and payload[6] stores T6's value. Guard is also separate per-invocation synchronization storage; guard[1] is the signal associated with payload[1]. There is no extra swap-style temporary variable in the test. The two endpoints connect through release/acquire: T1 writes payload[1], releases and signals guard[1]; T6 observes/acquires guard[1], then reads payload[1].

lanes paired, slots indexed, three buffers bound←/→ · N notes · S presenter · O overview
The top diagram shows the eight active subgroup lanes paired by XOR with size - 1 (here size = 8). The shader pairs lane i with lane i ^ 7, so the pairs are (0↔7), (1↔6), (2↔5), (3↔4). Each lane has a localId, and the linearization formula is bufferCoord = (gl_WorkGroupID.y * NUM_WORKGROUP_EACH_DIM + gl_WorkGroupID.x) * DIM * DIM + localId.y * DIM + localId.x, and partnerBufferCoord uses subgroupShuffleXor(localId, size - 1) before the same linearization. The bottom row introduces the three host-bound resources: payload at binding 0, guard at binding 1, fail at binding 2. All three are SSBOs at descriptor set 0. Slot indices on each card match the lane index; in the guard card slot 1 is highlighted to suggest "this lane already signaled its guard" — a snapshot of the protocol that page 08 will explain step by step. No GLSL or SPIR-V here; the next slide walks the four-step protocol with the reconstructed shader.
